### 第 1 项：自适应帧率（设计已确认）

- 待机（未按瞄准键）：采集帧率 60fps，省 CPU / 带宽 / 温度；
- 瞄准（按住瞄准键）：采集帧率 = `dxgi_target_fps`（默认取显示器刷新率；本机游戏 ~170fps 建议填 180）；
- 实现方式：dxcam 无运行时改帧率接口，用 stop/start 重启采集线程（毫秒级、不重建复制通道，切换瞬间丢 1~2 帧可接受）；
- 自整定（后续增强）：从采集帧时间戳估算实际内容更新率，动态跟随游戏帧率。

### 第 2 项：动态预判与增强瞄准（设计已确认）

- 延迟补偿：预判时间 = 截图年龄 + 实测推理延迟 + 移动生效延迟（遥测实测）；
- 状态估计：自适应 EMA 平滑（方向一致 → alpha 大、响应快；方向杂乱/静止 → alpha 小、压噪声），替代原版固定重平滑；
- 运动模型：二阶（位置 + 速度×T + ½加速度×T²），加速度平滑 + 限幅，检测到方向反转时退回一阶防过冲；
- 增强瞄准（强锁）：目标平滑速度连续 2 帧 < 低速阈值（默认 40px/s）**且**预测点落在独立锁定框内（默认 ±30px，框外不触发）→ 跳过平滑，用 `误差 × 强增益`（默认 ×2.5，单帧封顶 ±60px）强行锁定；速度 > 高速阈值（默认 80px/s）回归正常；进/出阈值滞回防抖；
- 保留贝塞尔抖动叠加在强锁移动上，避免非人急停；
- 与原版行为并存：`prediction_mode: original / v2` 可切换；
- 验证：测试模式指标（超前量 / 横向偏差 / 落后占比 + 锁定框内收敛帧数）闭环对比。

## 一、性能优化（代码层）

### 1.1 推理链路

- **EP 自动选择**：`CUDA(FP32) → DML → CPU`，启动时用
  `ort.get_available_providers()` 探测；配置 `inference_provider` 可覆盖。
  FP32 全程无精度损失。
- **会话优化**：`GraphOptimizationLevel.ORT_ENABLE_ALL`、
  `intra_op_num_threads = os.cpu_count()`、`enable_cpu_mem_arena`。
- **张量复用**：预分配输入 buffer，避免每帧重新分配 numpy。
- ~~FP16~~：砍掉（精度妥协，用户否决）。
- TensorRT：仅 FP32 模式，留扩展（转换复杂度高，CUDA 不够快再上）。

### 1.2 截图

- `screen_size()/screen_center()` 启动时缓存，去掉每帧 GetSystemMetrics。
- dxcam 已零拷贝；区域最小化保持现状。

### 1.3 循环调度

- 高精度计时（`time.perf_counter`）精确限帧，去掉忙等。
- 流水线并行：留作 config 开关的实验功能，用遥测对比延迟分布再定默认。

### 1.4 延迟补偿

- 预测时间 = 配置 `tracker_prediction_time` + 实测推理延迟（遥测提供），
  待遥测数据支撑后实现并验证。

## 实施顺序

### 结论更新（2026-08-07）
- 动态 P 大误差段公式：用户确认为**后续研究点**，默认路径不触发，低风险。
- bezier_curve_steps：Frida 证据确认原版瞄准热路径不读取（3771 次读取仅 enabled/strength），属 UI 占位，**不实现**段数逻辑。
- 延迟补偿（阶段 2）：遥测显示移动目标预判平均超前 +8.5px、理想约 +31px（管线延迟 × 速度），滞后源于预判时间不足与速度平滑过重；待测试模式数据支撑后调优。
- 原版"帧率无上限"= `max_screenshot_inference_fps: 0`，是 AI 循环不封顶（实际速度=推理耗时），并非自适应游戏帧率；采集帧率另由 `dxgi_target_fps` 决定。
- 推理 p90 尖峰（333ms）：实为 **bug**——`swap_model_if_changed` 用相对路径与绝对路径比较，永远不等，导致每秒重载模型（87~1000ms）。已直接修复（比较前先解析绝对路径）；按约定 bug 不入优化清单。
